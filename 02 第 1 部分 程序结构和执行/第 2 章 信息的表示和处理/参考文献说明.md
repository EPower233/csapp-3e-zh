# 参考文献说明

[返回章节目录](./%E7%AC%AC2%E7%AB%A0%20%E4%BF%A1%E6%81%AF%E7%9A%84%E8%A1%A8%E7%A4%BA%E5%92%8C%E5%A4%84%E7%90%86.md)

关于 C 语言的参考书\[[45](../../05%20%E9%99%84%E5%BD%95%E4%B8%8E%E5%8F%82%E8%80%83%E6%96%87%E7%8C%AE/%E5%8F%82%E8%80%83%E6%96%87%E7%8C%AE.md#%E6%96%87%E7%8C%AE%2045), [61](../../05%20%E9%99%84%E5%BD%95%E4%B8%8E%E5%8F%82%E8%80%83%E6%96%87%E7%8C%AE/%E5%8F%82%E8%80%83%E6%96%87%E7%8C%AE.md#%E6%96%87%E7%8C%AE%2061)\]讨论了不同的数据类型和运算的属性。（这两本书中，只有 Steele 和 Harbison 的书[\[45\]](../../05%20%E9%99%84%E5%BD%95%E4%B8%8E%E5%8F%82%E8%80%83%E6%96%87%E7%8C%AE/%E5%8F%82%E8%80%83%E6%96%87%E7%8C%AE.md#%E6%96%87%E7%8C%AE%2045)涵盖了 ISO C99 中的新特性。目前还没有看到任何涉及 ISO C11 新特性的书籍。）对于精确的字长或者数字编码 C 语言标准没有详细的定义。这些细节是故意省去的，这样可以在更大范围的不同机器上实现 C 语言。已经有几本书\[[59](../../05%20%E9%99%84%E5%BD%95%E4%B8%8E%E5%8F%82%E8%80%83%E6%96%87%E7%8C%AE/%E5%8F%82%E8%80%83%E6%96%87%E7%8C%AE.md#%E6%96%87%E7%8C%AE%2059), [74](../../05%20%E9%99%84%E5%BD%95%E4%B8%8E%E5%8F%82%E8%80%83%E6%96%87%E7%8C%AE/%E5%8F%82%E8%80%83%E6%96%87%E7%8C%AE.md#%E6%96%87%E7%8C%AE%2074)\]给了 C 语言程序员一些建议，警告他们关于溢出、隐式强制类型转换到无符号数，以及其他一些已经在这一章中谈及的陷阱。这些书还提供了对变量命名、编码风格和代码测试的有益建议。Seacord 的书[\[97\]](../../05%20%E9%99%84%E5%BD%95%E4%B8%8E%E5%8F%82%E8%80%83%E6%96%87%E7%8C%AE/%E5%8F%82%E8%80%83%E6%96%87%E7%8C%AE.md#%E6%96%87%E7%8C%AE%2097)是关于 C 和 C++ 程序中的安全问题的，本书结合了 C 程序的有关信息，介绍了如何编译和执行程序，以及漏洞是如何造成的。关于 Java 的书（我们推荐 Java 语言的创始人 James Gosling 参与编写的一本书[\[5\]](../../05%20%E9%99%84%E5%BD%95%E4%B8%8E%E5%8F%82%E8%80%83%E6%96%87%E7%8C%AE/%E5%8F%82%E8%80%83%E6%96%87%E7%8C%AE.md#%E6%96%87%E7%8C%AE%205)）描述了 Java 支持的数据格式和算术运算。

关于逻辑设计的书\[[58](../../05%20%E9%99%84%E5%BD%95%E4%B8%8E%E5%8F%82%E8%80%83%E6%96%87%E7%8C%AE/%E5%8F%82%E8%80%83%E6%96%87%E7%8C%AE.md#%E6%96%87%E7%8C%AE%2058), [116](../../05%20%E9%99%84%E5%BD%95%E4%B8%8E%E5%8F%82%E8%80%83%E6%96%87%E7%8C%AE/%E5%8F%82%E8%80%83%E6%96%87%E7%8C%AE.md#%E6%96%87%E7%8C%AE%20116)\]都有关于编码和算术运算的章节，描述了实现算术电路的不同方式。Overton 的关于 IEEE 浮点数的书[\[82\]](../../05%20%E9%99%84%E5%BD%95%E4%B8%8E%E5%8F%82%E8%80%83%E6%96%87%E7%8C%AE/%E5%8F%82%E8%80%83%E6%96%87%E7%8C%AE.md#%E6%96%87%E7%8C%AE%2082)，从数字应用程序员的角度，详细描述了格式和属性。
